# 1Freq-FM7 Programmer

Консольная программа Windows x86 для программирования **ATmega328P через USBasp по ISP**. Программа работает с Flash-прошивкой и пятью параметрами EEPROM. Это специализированная утилита для проекта 1Freq-FM7, а не универсальный AVR-программатор.

## Что понадобится

- **Программатор USBasp** — оригинальный Thomas Fischl или совместимый клон с прошивкой USBasp. Программа жёстко использует протокол AVRDUDE `-c usbasp`; другие типы программаторов не поддерживаются.
- **ISP-разъём и кабель** — стандартный 10-контактный USBasp либо переходник на 6-контактный ISP. Должны быть подключены сигналы VCC, GND, RESET, MOSI, MISO и SCK.
- **Драйвер USBasp для Windows**. Его нужно установить отдельно до запуска программы. Программа драйвер не устанавливает и COM-порт не использует.
- Целевая плата с ATmega328P, доступными ISP-сигналами и подходящим питанием.

Официальное описание программатора: [USBasp — Thomas Fischl](https://www.fischl.de/usbasp/).

### Что не подходит

USBtinyISP, Arduino as ISP, AVRISP/AVRISP mkII, CH341A и обычные USB–UART адаптеры этой версией программы не поддерживаются. Для них нужны другие параметры и/или другой протокол AVRDUDE.

**Скорость ISP фиксирована: 32 кГц** (`-B 32kHz`). Программа передаёт этот параметр AVRDUDE автоматически во всех операциях с микроконтроллером.

## Подготовка и первый запуск

1. Установите драйвер USBasp и подключите программатор к USB компьютера.
2. Подключите ISP-кабель к плате ATmega328P. Проверьте ориентацию разъёма и соответствие сигналов. Плата должна быть запитана корректным для неё напряжением. Не включайте одновременно питание от USBasp и внешний источник, если схема платы и положение перемычек этого не предусматривают.
3. Распакуйте переносной комплект в отдельную папку.
4. Запускайте `1Freq-FM7-Programmer.exe` из этой папки. Не отделяйте EXE от файлов AVRDUDE и его DLL.

В рабочей папке должны находиться:

- `1Freq-FM7-Programmer.exe` — сама программа;
- `avrdude.exe`, `avrdude.conf` и DLL из комплекта — обмен с USBasp;
- `ATmega328P.hex` — файл прошивки для пункта 3;
- `eeprom.hex` — файл параметров EEPROM для пунктов 2 и 4.

В готовом переносном ZIP эти файлы лежат вместе, в одной папке. Драйвер USBasp в ZIP не входит и устанавливается в Windows отдельно.

**Рекомендуемый первый шаг на уже настроенном устройстве — пункт 1, чтение EEPROM.** Он сохранит текущие 80 байт параметров в файл и, если файл уже существовал, оставит его копию с датой и временем. Только после этого переходите к редактированию или записи.

## Главное меню

| Пункт | Название | Что делает |
|---:|---|---|
| **1** | Считать EEPROM из микроконтроллера | Считывает EEPROM, сохраняет первые 80 байт в `eeprom.hex`. |
| **2** | Редактировать EEPROM-файл | Меняет параметры XT, MD, F1, F2 и ST в `eeprom.hex`. К программатору не обращается. |
| **3** | Прошивка Firmware и Fuse | Записывает и проверяет Fuse, затем записывает и проверяет Flash из `ATmega328P.hex`. EEPROM этой операцией не читается и не записывается. |
| **4** | Записать только EEPROM | Проверяет `eeprom.hex`, записывает и проверяет только 80 байт EEPROM. Flash и Fuse не меняет. |
| **5** | Выход | Завершает программу. |

Перед операцией записи программа показывает, что будет сделано, и запрашивает подтверждение.

### 1. Считать EEPROM из микроконтроллера

- Читает EEPROM через USBasp во временный бинарный файл.
- Из считанного содержимого берёт первые **80 байт**, адреса `0x00–0x4F`, и формирует пять записей Intel HEX по 16 байт.
- Считанные байты сохраняются без изменения значений: редакторские диапазоны здесь не применяются. Например, число `9999999999` не обрезается до 32 бит.
- Если рядом уже есть `eeprom.hex`, после успешного чтения старый файл переименовывается в `eeprom_old_ГГГГ-ММ-ДД_ЧЧ-ММ-СС.hex`.
- При ошибке чтения существующий `eeprom.hex` остаётся на месте.

Данные EEPROM за пределами адреса `0x4F` в этот файл не попадают.

### 2. Редактировать EEPROM-файл

Редактор изменяет только файл `eeprom.hex`; подключённый микроконтроллер не программируется.

| Параметр | Назначение | Допустимый ввод | Значение по умолчанию |
|---|---|---:|---:|
| XT | Частота опорного генератора | 5 000 000 – 110 000 000 Гц | 27 007 840 |
| MD | Режим работы | 5 или 6 | 5 |
| F1 | Частота при минимальном напряжении | 15 000 – 300 000 000 Гц | 2 000 000 |
| F2 | Частота при максимальном напряжении | 15 000 – 300 000 000 Гц | 1 000 000 |
| ST | Дополнительный параметр | 0 – 1024 | 0 |

Диапазон проверяется только для нового значения, введённого с клавиатуры. **Enter оставляет текущее значение без изменений**, даже если оно выходит за пределы диапазона редактора. Это позволяет прочитать EEPROM старого устройства и записать считанные значения обратно, не меняя их.

### 3. Прошивка Firmware и Fuse

Пункт 3 выполняет операции в строгом порядке:

1. Записывает Fuse-биты.
2. Считывает и проверяет записанные Fuse.
3. Записывает Flash из `ATmega328P.hex`.
4. Проверяет Flash после записи.

Используются фиксированные значения:

| Fuse | Значение |
|---|---:|
| LFUSE | `0x62` |
| HFUSE | `0xD1` |
| EFUSE | `0xFF` |

`HFUSE=0xD1` включает EESAVE — сохранение EEPROM при Chip Erase. Fuse сначала проверяются; если запись или проверка Fuse не прошла, переход к записи Flash не выполняется.

**Пункт 3 не читает и не записывает файл `eeprom.hex` и не выполняет команд записи EEPROM.** При штатно записанном и проверенном HFUSE EEPROM должна сохраниться при стирании Flash.

Не используйте этот пункт с другим типом микроконтроллера или платой с иной конфигурацией Fuse: значения заданы для данного проекта.

### 4. Записать только EEPROM

- Проверяет структуру `eeprom.hex`, контрольные суммы, адреса и размер записей.
- Записывает ровно пять записей по 16 байт — **80 байт, адреса `0x00–0x4F`**.
- Выполняет проверку EEPROM после записи.
- Не записывает Flash, не меняет Fuse и не считывает EEPROM микроконтроллера перед записью.

Пункт 4 не ограничивает значения диапазонами редактора: ранее считанные корректно оформленные значения, в том числе `9999999999`, можно записать обратно.

## Формат EEPROM

Файл `eeprom.hex` — Intel HEX с пятью записями данных по 16 байт:

| Адрес | Метка |
|---:|---|
| `0x00` | XT |
| `0x10` | MD |
| `0x20` | F1 |
| `0x30` | F2 |
| `0x40` | ST |

В каждой 16-байтовой записи хранится ASCII-текст вида `TAG=число`, остаток записи заполняется нулевыми байтами. Суммарно редактируемая область занимает 80 байт.

## Совместимость и сборка

- Программа собирается как **32-битное Windows-приложение x86**, консольная подсистема версии **5.01** — целевая совместимость Windows XP SP3.
- На 64-битных версиях Windows 32-битная программа запускается через WoW64.
- В комплекте используется AVRDUDE x86, который выбирается сборкой после проверок формата PE32, версии подсистемы Windows и импортируемых API.
- Фактическую работу готового комплекта на Windows XP SP3, конкретном USBasp и целевой плате необходимо подтвердить на реальном оборудовании.

Для локальной сборки используется `build-xp-x86.cmd`; рядом должна быть папка `toolchain` с переносным TDM-GCC. `package.cmd` собирает переносную папку `dist/1Freq-FM7-Programmer`. В GitHub Actions сборка дополнительно запускает `--self-test`, проверяет архитектуру и версию Windows subsystem у EXE и публикует собранный EXE в этот каталог.


## Где взять готовую программу

Собранный `1Freq-FM7-Programmer.exe` публикуется прямо в этом каталоге репозитория. Его можно скачать отдельно, но для работы рядом с ним всё равно нужны `avrdude.exe`, `avrdude.conf` и DLL.

Полный переносной комплект формируется GitHub Actions. Откройте вкладку **Actions**, выберите последний успешный запуск **Build 1Freq-FM7 Programmer bundle** и скачайте артефакт **1Freq-FM7-Programmer-Portable**. Внутри ZIP все рабочие файлы лежат в одной папке. Артефакты GitHub Actions хранятся 30 дней; сам EXE также остаётся в каталоге репозитория.
