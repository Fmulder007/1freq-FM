# 1freq-FM Console

Специализированное Windows-консольное приложение для настройки и прошивки микросинтезатора на Si5351.

Приложение размещено отдельно от исходников прошивки FM7. Оно не изменяет скетч, библиотеки и генератор EEPROM в родительском каталоге.

## Что умеет

- создавать EEPROM-конфигурацию FM7 с теми же пятью параметрами и ограничениями, что и make_eeprom.ps1;
- распознавать целевой микроконтроллер по трёхбайтовой сигнатуре;
- выбирать правильный HEX из каталога Firmware;
- работать с USBasp;
- работать с подготовленной пользователем Arduino Nano с официальным скетчем ArduinoISP через STK500v1, COM-порт и 19200 бод;
- сохранять EEPROM перед стиранием Flash и перед отдельной записью EEPROM;
- записывать и проверять Fuse-биты из профиля МК по выбору пользователя;
- записывать и проверять Flash и EEPROM;
- считывать EEPROM в резервную копию;
- запускать Zadig по отдельной команде, не меняя драйвер автоматически;
- запоминать последний выбранный программатор и COM-порт.

Все запросы ввода используют единый порядок: назначение, допустимый диапазон или варианты, значение по умолчанию в квадратных скобках, затем двоеточие. Enter оставляет предложенное значение; в подтверждениях Enter означает безопасный ответ «НЕТ».

## Поддерживаемые МК

Список и все параметры находятся в Config/devices.json, а не в исполняемом коде приложения.

| МК | Сигнатура | AVRDUDE part | Flash | EEPROM |
|---|---|---|---:|---:|
| ATmega168 | 1E 94 06 | m168 | 16 КБ | 512 Б |
| ATmega168P / PA | 1E 94 0B | m168p | 16 КБ | 512 Б |
| ATmega328P | 1E 95 0F | m328p | 32 КБ | 1 КБ |
| ATmega328PB | 1E 95 16 | m328pb | 32 КБ | 1 КБ |

Для P/PA используется один профиль: у этих вариантов одинаковая сигнатура, поэтому по одной сигнатуре различить их нельзя. В devices.json их следует представлять одним профилем с aliases, а не дублировать сигнатуру.

Для каждого профиля указан отдельный файл прошивки. Приложение не будет прошивать HEX от ATmega328P в ATmega328PB или ATmega168.

На момент создания исходного комплекта готовые бинарные HEX-файлы МК не приложены: их нужно отдельно скомпилировать и испытать. Пока нужного файла нет в Firmware, пункт прошивки для этого МК не продолжится.

## Программаторы

### USBasp

Используется обычный USBasp со стандартной прошивкой. AVRDUDE вызывается с программатором usbasp.

Zadig находится в Tools/Zadig.exe. Он запускается только через пункт меню 6. Выбирать в Zadig следует именно USBasp и только при необходимости менять его драйвер. Для Nano через Zadig ничего делать не нужно.

### Arduino Nano как ISP

Nano должна быть заранее подготовлена пользователем: в ней уже должен работать официальный скетч ArduinoISP, загруженный средствами Arduino IDE.

Приложение не устанавливает Arduino IDE, не загружает ArduinoISP и не перепрошивает Nano. Оно только выбирает COM-порт и обращается к ArduinoISP через протокол STK500v1 на 19200 бод.

При подключении Nano к ПК открытие COM-порта может вызвать автоматический сброс Nano в загрузчик. В стандартной схеме ArduinoISP обычно ставят конденсатор около 10 мкФ между RESET и GND Nano-программатора после загрузки ArduinoISP. Перед подключением проверьте схему и не соединяйте два независимых источника питания.

Типовая ISP-разводка Nano → целевой МК:

| Nano | Целевая плата |
|---|---|
| D10 | RESET |
| D11 | MOSI |
| D12 | MISO |
| D13 | SCK |
| GND | GND |
| 5V | VCC, только если питание подаётся от Nano |

Если на целевой плате отдельное питание, линию 5V не соединять; общая земля при этом обязательна. Уровни логики должны быть совместимы.

## EEPROM FM7

Приложение использует схему из текущей прошивки FM7:

| Адрес | Метка | Назначение |
|---:|---|---|
| 0x00 | XT= | Опорная частота кварца Si5351, Гц |
| 0x10 | MD= | Режим 5 или 6 |
| 0x20 | F1= | Частота при минимальном напряжении PC0 |
| 0x30 | F2= | Частота при максимальном напряжении PC0 |
| 0x40 | ST= | Количество шагов, 0 = 1024 |

Одна запись занимает 16 байт; полный блок настроек — 80 байт.

Ограничения повторяют прошивку и генератор из Code/1freq-FM7:
- XT: 5 000 000…110 000 000 Гц;
- MD: 5 или 6;
- F1 и F2: 15 000…300 000 000 Гц;
- ST: 0…1024.

Параметры EEPROM описаны в Config/devices.json. Формирование Intel HEX выполняется внутри приложения, без запуска PowerShell-скрипта.

Последний выбор программатора и COM-порта сохраняется отдельно в Data/app-state.json; это не меняет каталог устройств и его параметры.

## Важная последовательность при прошивке

При записи Flash AVRDUDE обычно выполняет Chip Erase. В зависимости от Fuse EESAVE это может стереть EEPROM. Поэтому программа действует в таком порядке:

1. определяет МК;
2. считывает EEPROM в Backup;
3. записывает Flash;
4. отдельно проверяет Flash;
5. записывает свежие параметры FM7 в EEPROM;
6. проверяет EEPROM.

Если чтение EEPROM перед прошивкой не удалось, запись Flash отменяется. Перед прошивкой HEX приложение предлагает: записать Fuse-биты из профиля, оставить их без изменений или вернуться назад. По Enter выбран безопасный вариант «только HEX». Значения LFUSE/HFUSE/EFUSE находятся в Config/devices.json и сейчас соответствуют заводским значениям из документации Microchip. Это именно заводские настройки кристалла (внутренний RC 8 МГц с делителем /8, то есть 1 МГц CPU), а не настройки под кварц конкретной платы. Перед записью Fuse-биты показываются на экране, после записи AVRDUDE читает и проверяет все три байта. При ошибке проверки запись Flash отменяется.

## Заводские Fuse-биты в профилях

Значения в каталоге сейчас заданы по заводским таблицам документации Microchip:

| МК | LFUSE | HFUSE | EFUSE |
|---|---:|---:|---:|
| ATmega168 | 0x62 | 0xDF | 0xF9 |
| ATmega168P / PA | 0x62 | 0xDF | 0xF9 |
| ATmega328P | 0x62 | 0xD9 | 0xFF |
| ATmega328PB | 0x62 | 0xD9 | 0xF7 |

Это временные исходные значения для проверки самого механизма. Они не оптимизированы под кварц или другую тактовую схему конкретной платы. Изменить их можно непосредственно в соответствующем объекте профиля в Config/devices.json. Lock-биты приложением не записываются.

## Добавление нового микроконтроллера без перекомпиляции

1. Добавьте профиль с уникальной сигнатурой в Config/devices.json.
2. Укажите точный avrdudePart, имя отдельного HEX, объём Flash и EEPROM, формат EEPROM и допустимые программаторы.
3. Если установленный AVRDUDE не знает part, добавьте его техническое описание в Config/avrdude-extra.conf.
4. Положите проверенный HEX в Firmware под именем из профиля.

Приложение проверяет каталог при старте: ID и сигнатуры должны быть уникальны, размеры памяти должны вмещать 80 байт FM7, а имена HEX не должны выходить за каталог Firmware.

Если новый МК использует неизвестный AVRDUDE алгоритм или новый протокол программирования, одного JSON-профиля недостаточно — понадобится версия AVRDUDE с поддержкой этого алгоритма. Для обычных AVR с поддерживаемым ISP профиля и, при необходимости, part-описания достаточно.

## Сборка и публикация

Для разработчика:
1. Установить .NET 10 SDK на Windows x64.
2. Запустить publish.cmd.
3. Скрипт при необходимости скачает официальные инструменты, проверит SHA-256 AVRDUDE и цифровую подпись Zadig, затем соберёт самодостаточное приложение.
4. Готовый ZIP появится в dist/1freq-FM-Console-win-x64.zip.

Пользователю готового ZIP не нужен установленный .NET Runtime или Arduino IDE для работы с USBasp. Arduino IDE нужна только тому, кто самостоятельно подготавливает Nano как ArduinoISP.

Для Arduino Nano выбран AVRDUDE 8.3 MinGW x64: официальный MSVC-вариант AVRDUDE 8.3 не содержит libserialport и поэтому не подходит для COM-связи с Arduino as ISP. Это ограничение указано в официальных release notes AVRDUDE.

## Проверки и ограничения текущего исходного этапа

В этом исходном комплекте:
- конфигурация каталога и EEPROM проверяется командой 1freq-FM.exe --self-test;
- полноценная AVRDUDE-прошивка должна быть проверена на реальном USBasp и на Nano с ArduinoISP;
- готовые HEX для целевых МК не добавлены;
- компиляцию .NET-проекта в этой среде выполнить не удалось, поскольку здесь отсутствует .NET SDK.

Исходники проекта и скрипты сборки размещены в этом каталоге; это ещё не готовый к раздаче ZIP с EXE и прошивками МК.
